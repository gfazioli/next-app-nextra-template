# API

The template ships three read-only `GET` routes, all in the `app/api` folder:

| Route                  | Returns                                                     |
| ---------------------- | ----------------------------------------------------------- |
| `/api/search`          | Pagefind search results, computed on the server             |
| `/api/github-releases` | The latest releases of the repository set in `config/index.ts` |
| `/api/version`         | The app's version, read from `package.json`                 |

## Search API

Since Nextra 4 the search engine is built in and uses [Pagefind](https://pagefind.app/), which indexes the built HTML and searches it in the browser. This route runs the same index on the server, with a small shim for the browser globals Pagefind expects 👏

Try it with [a search for “mantine”](/api/search?q=mantine).

### Query parameters

- `q`: the search query, at least 3 characters.
- `limit`: the maximum number of results (default `5`). There is no paging: the route returns the first `limit` results.
- `excerptLength`: the length of each excerpt, in words (default `30`).

The parameter names and their defaults live in `config/index.ts`:

```ts filename="config/index.ts"
  /**
   * Search configuration (for pagefind)
   * This is used to configure the search engine API.
   * @see /app/api/search/route.ts
   */
  search: {
    queryKeyword: 'q',
    minQueryLength: 3,
    limitKeyword: 'limit',
    defaultMaxResults: 5,
    excerptLengthKeyword: 'excerptLength',
    defaultExcerptLength: 30,
    defaultLanguage: 'en',
  },
```

### Response

An array with one entry per matching page. Each of its `items` is a section of that page, with a link straight to it and the matched words wrapped in `<mark>`:

```json
[
  {
    "title": "Mantine",
    "content": "The text of the page, as Pagefind indexed it",
    "items": [
      {
        "title": "Third-party components",
        "url": "https://your-site.com/docs/mantine#third-party-components",
        "excerpt": "… you can use the <mark>Mantine</mark> Marquee components in your …"
      }
    ]
  }
]
```

In TypeScript:

```ts
interface Item {
  title: string;
  url: string;
  excerpt: string;
}

interface Result {
  title: string;
  content: string;
  items: Item[];
}

type SearchResponse = Result[];
```

The URLs are absolute and open the page itself.

### Errors

Errors come back as an object with an `error` key, two of them with status `200`: check for the key rather than the status.

| Case                           | Status | Body                                   |
| ------------------------------ | ------ | -------------------------------------- |
| `q` is missing                 | 200    | `{ "error": "No search query provided" }` |
| `q` is shorter than 3 characters | 200  | `{ "error": "Search query too short" }`   |
| The search itself fails        | 500    | `{ "error": "Search failed" }`            |

> [!NOTE]
>
> The index files are written by `yarn build` into `public/_pagefind/`, and git ignores them. Under `yarn dev` the route has nothing to search until a build has run once, just like Nextra's search box.

## GitHub Release API

`/api/github-releases` proxies the GitHub REST API and returns the latest releases of the repository set in `config/index.ts`: as many as `releaseNotes.maxReleases`, 10 by default. The [Release Notes](/docs/release-notes) page is built on it.

### Response

```json
{
  "releases": [],
  "status": "ok"
}
```

`releases` holds GitHub's own release objects, newest first (`tag_name`, `name`, `body`, `published_at`, `html_url` and the rest), exactly as GitHub's [List releases](https://docs.github.com/en/rest/releases/releases#list-releases) endpoint returns them.

### Refused requests and errors

| Case                                                                  | Status        | Body                                    |
| --------------------------------------------------------------------- | ------------- | --------------------------------------- |
| No `User-Agent` header                                                | 400           | `{ "error": "User agent not found" }`   |
| A `User-Agent` that looks like a crawler (`bot`, `crawl`, `slurp`, `spider`) | 403    | `{ "error": "Bots are not allowed" }`   |
| GitHub answers with an error                                          | GitHub's own  | `{ "error": "<GitHub's status text>" }` |
| Anything else goes wrong                                              | 500           | `{ "error": "Internal server error", "details": "…" }` |

### Caching

The call to GitHub is cached for an hour (`next: { revalidate: 3600 }`), and the route answers with `Cache-Control: public, s-maxage=3600, stale-while-revalidate=86400`: a CDN such as Vercel's serves the same response for an hour, and a stale one for up to a day while it refreshes.

### Config

```ts filename="config/index.ts"
  /**
   * GitHub API configuration
   * @see https://docs.github.com/en/rest/reference/repos#releases
   *
   * The GitHub API token is optional for rate limiting.
   * If you want to use it, create a read-only token: a fine-grained token with
   * public repositories (read-only), or a classic token with no scopes.
   *
   * This information is used to fetch the releases from the GitHub API.
   */
  gitHub: {
    repo: 'gfazioli/next-app-nextra-template',
    apiUrl: 'https://api.github.com',
    releasesUrl: 'https://api.github.com/repos/gfazioli/next-app-nextra-template/releases',
  },
  ...
  /**
   * Release notes configuration
   * This is used to link the release notes in the app.
   */
  releaseNotes: {
    url: 'https://github.com/gfazioli/next-app-nextra-template/releases',
    maxReleases: 10,
  },
```

`repo` is also sent to GitHub as the request's `User-Agent`, which GitHub requires.

### Rate limiting and `GITHUB_TOKEN`

Without a token, GitHub allows 60 requests per hour from each IP address; with a token, 5,000 per hour. To use one, set the `GITHUB_TOKEN` environment variable: the route reads it on its own, with no code to change. If GitHub rejects the token (a `401`, or a `403` that is not a rate limit), the route retries without it, since public releases can be read anonymously.

A read-only token is enough, as the config comment above says: the `repo` scope is not needed, and it would grant full access to your private repositories.

## Version API

`/api/version` returns the `version` field of `package.json`, for example:

```json
{ "version": "1.0.0" }
```
